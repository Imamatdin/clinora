## Delivered behavior

`npm ci`, `npm run check`, `npm start` run the new local application without hidden
environment files, a database or provider credentials. React status screen and Node
health API work together; the same compiled server serves generated browser assets.
Clinical API paths reject access, even when callers supply role/cookie/bearer claims.
The UI labels authentication, records and integrations as unimplemented/unavailable;
it contains no simulated clinical controls or patient data.

Runtime-validated contracts cover account/verification/membership, clinic-scoped
patients and dated encounters, diagnosis history, revisioned transcript evidence,
clinical field provenance, append-only document versions/amendments, exact-version
approvals, patient/Telegram identity links, integration status and typed API errors.
Server-only access, approval/export and uncertain-dispatch policy primitives are
implemented and tested. Repository/adapter interfaces are **contracts only**: no
database persistence, login, clinical approval transaction, capture, AI, queue,
Telegram flow or external adapter exists in the new core. No clinical validation.
