## Delivered behavior

- **Telegram link**: a manager presses "Invite to Telegram" on a staff member (or anyone links themselves from "PIN and Telegram"). The invite is single-use, valid 72 h, stored as SHA-256, shown as a `t.me/<bot>?start=` link plus a QR code. A new invite revokes the older one. The bot asks "Are you <name> (<clinic>)?" and binds the `from.id` of the user who taps confirm. Unlink takes one button and ends Telegram sessions at once. Managers can only invite or unlink accounts their clinic manages; a CEO's account needs a CEO.
- **Webhook** `POST /api/telegram/webhook`: the secret-token header is compared in constant time before the body is read, else 401 and nothing happens. Each `update_id` is processed once; replies are sent after commit and never retried.
- **Mini App sign-in** `POST /api/telegram/session`: HMAC-SHA256 check with the bot-derived key, `auth_date` no older than 1 h, single use (replay table), then the server requires a link, an active account and an active membership with a role. Result: a normal server session (`via='telegram'`). Unlinked or blocked users get the plain "ask your administrator" screen.
- **Shared PCs**: a manager enrols a PC, gets an httpOnly device cookie (stored hashed, revocable) and is signed out. Staff then pick their name and enter a 4-6 digit PIN (scrypt, simple PINs refused). Device sessions are bound to the device cookie, reach only the device's clinic, and the **server** ends them after 10 min idle; the browser also locks on idle and on "Switch user". After 5 wrong PINs the account locks (per account, never per IP) until a manager unlocks it or the person sets a new PIN from their own session. Password sign-in on an enrolled PC also becomes a device session. PINs cannot be changed from a device session.
- **Installed app**: manifest, icons from a new SVG mark (the repo had no logo file), a service worker that caches the shell only and never touches `/api`, an Install button (Chrome/Edge) and Add-to-Home-Screen steps on iOS.
- **Headers**: CSP unchanged except `frame-ancestors https://web.telegram.org`. `script-src 'self'` holds because `src/web/access/telegram.ts` is our own bridge; Telegram's script is not loaded.
- **Notices** `notifyStaff()`: send by role or account id to linked, active staff. Templates accept only integers (fixed text plus an "Open Clinora" button). Nothing calls it yet; C4/C6 will wire it.
- **UI**: Telegram theme colours, native back button, large buttons, PIN pad. Strings live in `access.*` in uz-Cyrl, uz-Latn and ru (only uz-Cyrl is active until the locale switch lands). Bot text is in all three languages.

## Decisions and changes

- Linking via Telegram retires a temporary password that was never changed, so the password the administrator saw stops working. Reversible in `links.ts::consumeInvite`.
- Mini App cookies use `SameSite=None; Secure; Partitioned` on HTTPS so they work inside the web.telegram.org iframe. Mutations still need Origin plus the CSRF token.
- Routes: `src/server/routes/access.ts` (one registry line). Invite creation and enrolment live in `src/server/access.ts`, because they need the bot name or set cookies. Shared edits: `notebook.ts` (actorFor, login, /me), `app.ts`, `main.ts`, `main.tsx`, `staff.tsx`, `style.css`, `uz-Cyrl.ts` (one part).
- New dependency `qrcode-generator@2.0.4` (MIT, no deps). Init-data algorithm cross-checked against aiogram 3.15. See `docs/REUSE-MANIFEST.md`.
- Env: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` (≥32 chars), `TELEGRAM_BOT_USERNAME`: all three or none, otherwise startup fails. On the host run `npm run telegram:setup`, which sets the webhook, menu button and /start.

## Remaining issues

- Needs Imamatdin: create the bot in BotFather, set the 3 env vars on staging, run `npm run telegram:setup`, then test on a real Android and iPhone Telegram plus web.telegram.org.
- Safari may block the partitioned cookie inside the web.telegram.org iframe. The phone apps (the main path) use a top-level webview and are not affected.
- PIN hashes cannot resist offline brute force if the database leaks (the space is only 10^4–10^6). The online guard is the per-account lockout.
- Bot notices use the clinic default language until per-person locale exists.
