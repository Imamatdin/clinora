## Decisions and changes

- Deployer identity gets Cloud Run Developer, Service Account User (runtime SA only) and Artifact Registry Writer (one repo). It does not get Cloud SQL Client or Secret Accessor: it never connects to the database. The runtime SA has those (secret-scoped). This differs from the brief, on purpose.
- Migrations run before traffic shifts, so they must stay backward-compatible. `/readyz` accepts extra newer migrations, so the old revision keeps serving.
- No session secret: sessions are random tokens stored as digests. Telegram and AI secrets are added by the tasks that need them.
- Region not chosen: measuring from this US sandbox would be meaningless, and gcping is blocked here. DEPLOY.md gives the decision rule. Domain mapping is region-limited; the alternative is a load balancer. Firebase Hosting ruled out (it forwards only the `__session` cookie).
- Rebase: `scripts/demo-catalog.ts` moved to `src/server/demo-catalog.ts` (one-line re-export left) so the compiled seed has 008's ten-doctor catalog. `scripts/demo.mjs` wraps `src/server/demo-seed.ts`, same local behavior. Kept 004's CSP (Telegram framing) and added HSTS. Telegram settings are injected from Secret Manager only when `GCP_TELEGRAM_BOT_USERNAME` is set (all three or none). Probes are host-level, not clinic routes, so they are not in the 008 route registry; no screens or strings were added.
- Changed: `Dockerfile`, `.dockerignore`, `.env.example`, `.github/workflows/{deploy,secret-scan}.yml`, `deploy/gcp/*`, `src/server/{app,database,main,notebook}.ts`, new `src/server/{client-ip,demo-guard,demo-seed,migrate-cli}.ts`, `tests/deploy.test.ts`, `tests/integration/deploy.test.ts`, `docs/{DEPLOY,THREAT-MODEL}.md`.
