## Delivered behavior

- **Doctor** (web module `module.myQueue`, phone first): the queue uses task 007's API (`queue/mine`, `queue/call-next`, `queue/tickets/:id/status`). I added to 007's `callNext`: one active patient per doctor, with a per-doctor lock, so several devices (or a manager on the doctor's point) pressing "Call next" call exactly one patient. "Did not come" moves the ticket from called back to waiting. Starting a visit creates the doctor's encounter on first open (a unique index allows one per doctor per visit). The patient card shows previous visits with diagnosis and lab results. The note has the 4 notebook fields plus structured prescription lines. Saving writes a draft version; approving writes an immutable confirmed version plus a `note_approvals` row that points to it. After approval, edits are amendments with a reason that reference the approval. The doctor can order services and lab tests (charge lines `ordered`, `source='doctor'`, priced with `priceAt`; unpriced services are refused). Completing the consultation moves the linked consultation charge line from ordered to completed once. Prescription: server-rendered A4 PDF built from the latest approved version only, with the version and approval ids in the PDF metadata and in the footer.
- **Lab** (`module.labOrders`; laboratory writes, CEO and administrator read): lab lines of the open day with a status filter. Results are saved as append-only `lab_results` versions guarded by an `expectedVersion` stale check. Confirming completes the charge line once; corrections after confirmation become new versions marked `afterConfirmation`. Lab routes return no note text and give no payment access.
- **003C fix:** the notebook timeline and editor show "Approved · revision N", or "Amending" while an amendment draft is open. Notebook saves after an approval need `amendmentReason` and are written as amendments. Notebook saves now keep fields written by other editors (prescription, assistant `gp.*`); before this change they silently dropped them. The assistant panel reloads the notebook after an approval. The assistant can no longer approve over a note that is already approved.
