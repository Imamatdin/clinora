## Delivered behavior
An enrolled registrar keeps registering and routing during disconnection; failed requests and browser offline events show a banner.
IndexedDB stores only registration fields, routing, business day, provisional code, timestamp and retry key, scoped to user/device/clinic.
Ordered replay uses the original keys; patient creation plus routing commits atomically, including recovery after a lost online response.
Provisional tickets print locally, with clinic/point/time and no patient name; real queue numbers appear alongside the provisional code after sync.
The server keeps the last 200 successful call mappings for two days per actor/clinic, so a reload can restore them without retaining queued patient data locally.
Duplicate patients, closed days and unavailable services stay in attention; staff select an existing patient, move to the open day, or reroute.
Queued data is cleared after successful sync, user switching and detected device/access revocation; incomplete routing remains resumable.
Session expiry and idle locking hide queued data without deleting it; PIN reauthentication by the same person restores it, while a different person clears it.
