Date: 13 November 2026, Asia/Tashkent. Branch `claude/audit-scale-deploy-1qu5lj` from `main` at `5ffc4d9`. Migration `026_report_scale.sql`.

## Delivered behavior
- **Reports read the range, not the history.** `records()` finds in-range visits through indexes, then fetches only their rows (plain rows, trimmed columns). Open balances come from SQL: `report_visit_open` (trigger-kept candidate set) plus visits with activity after the range end, priced by `report_line_parts` (set-based copy of the invoice arithmetic, used for doctor discount shares too). The response returns totals per doctor and per department, plus the 100 largest debtor visits (20 per group) and one remainder row. Payroll finalize inserts in batches.
- **Dashboard response bounded:** each drill-down list keeps its largest rows plus a "remaining (total)" row; sums are unchanged. A 30-day dashboard went from 36.7 MB to 0.96 MB. Exports and the stored day-close snapshot keep full detail. Zero-amount discount rows are no longer listed.
- **Full export streams** (`stream` route result): own READ ONLY REPEATABLE READ snapshot, role rechecked, cursor per table (2,000 rows), ZIP written as produced. The browser saves it as a Blob.
- **Migrations:** one transaction per file, `lock_timeout` 5 s with 6 retries (doubling back-off), statement timeout 15 min or per file (`-- clinora:statement_timeout=…`), session advisory lock. **Roles:** the migrate job runs as `clinora_migrator` and creates or updates `clinora_app` in SQL with DML only (no TRUNCATE/TRIGGER/CREATE/ownership; password stored as a SCRAM verifier; any `cloudsqlsuperuser` membership revoked). The migrate job has its own identity, `clinora-staging-migrate`. `bootstrap.sh`, `deploy.yml` and `docs/DEPLOY.md` are updated.
- **Assistant jobs:** chose CPU always allocated plus one minimum instance (about USD 45/month at Tier 1 list price, cost worked out in `service.yaml` and DEPLOY.md). Cloud Tasks was rejected for now (queue, auth endpoint, per-job idempotency). Request timeout raised to 300 s for the export.
- **Production checklist** in DEPLOY.md: separate project, separate secrets, role split, backups with a tested restore, release gates, alerting, the founders' real-data decision.
