# Task 003 — Browser capture, Telegram dictation and connected devices

Issued 12 November 2026. Read `../REMAINING-TASKS.md`, repository instructions, current contracts and the latest handoff first. Continue the existing application; this brief specifies new work, not delivered behavior.

## Outcome

An authorized clinician records a consultation in the browser or sends a native Telegram voice message, reviews and corrects its transcript, attaches it to the intended encounter, and sees the same saved result on another device. Recording, processing and persistence have distinct visible states. Live browser transcription updates during the consultation; Telegram dictation processes after the message arrives.

## Implementation

1. Extend the existing PostgreSQL model with capture sessions, media metadata, transcript revisions, processing jobs, Telegram links/link challenges and durable update receipts. Preserve existing encounters and manual notes. Use additive migrations and the same authority model; no second patient database. An unattached Telegram capture belongs to its clinician and selected clinic, not to an invented patient/encounter. Resolve this explicitly before instantiating the existing encounter-bound `TranscriptSegment` contract.
2. Put speech-to-text behind a server-side adapter with explicit language, audio format, segment/timestamp and failure contracts. Inspect the existing Aisha helper candidate, but select a provider using current official documentation, available credentials, measured target-language quality, latency and cost. Provider support for a language is not evidence of acceptable medical transcription. Record the choice and limits. Implement a real adapter; deterministic fixtures are for CI and visibly labelled demos only. Missing credentials must produce an unavailable state, never a fabricated transcript. A development assistant subscription is not an API credential or assumed inference budget.
3. Browser capture requires a deliberate start action, a visible recording indicator, stop/pause controls and an explicit recording-consent acknowledgement. Use capability detection for the actual device's MIME/codec. Support incremental transcription; do not wait for the complete consultation and call that live. A `MediaRecorder` chunk is not necessarily an independently decodable file: implement and test the provider's real framing/stream requirements. Release the microphone on stop/logout/navigation. Show permission denial, unsupported format, disconnected microphone, silence, provider failure and incomplete capture distinctly.
4. Assign immutable capture/chunk identities, sequence numbers, timestamps and checksums. Acknowledge only durable acceptance. Deduplicate retries and detect gaps/out-of-order chunks. Bound memory, upload size, recording duration, queue depth and per-clinic usage. Define what happens when the network fails, the tab closes or the phone locks. Recover acknowledged data after restart; clearly identify audio never received. Do not claim offline/background recording support without testing it. A small bounded in-memory retry buffer is acceptable; persistent browser storage of clinical audio requires a separately documented design.
5. Add durable job states, attempts, leases and bounded retry/backoff. Worker restarts must not produce duplicate final transcripts; stale worker completions must not overwrite newer results. Recheck authorization before processing, publishing and attaching results, including revocation while queued. Keep provider/network requests outside long database transactions. Cancellation and deletion must defeat late completions. Track usage and safe operational metadata without logging media URLs, tokens or clinical text.
6. Implement doctor Telegram linking from an authenticated workspace: expiring, hashed, single-use challenge; trusted Telegram sender identity; explicit confirmation of the pending Telegram identity back in the authenticated workspace before activation. A stolen/forwarded link must not silently link an attacker. Reject an already-linked conflicting identity; support unlinking and audit it. Linking never creates clinical membership. Use private chats for this increment and one explicit clinic context; no name/phone matching or patient role reuse.
7. Ingest native voice messages through the Bot API. Validate the configured webhook secret before parsing/processing, or document a single-owner long-polling mode with durable offsets. Deduplicate by bot/update identity and retain source-message identity. Acknowledge webhook receipt after durable enqueueing, not after expensive transcription. Fetch media only through trusted provider paths; validate content and resource limits rather than trusting filename/MIME claims. Do not accept arbitrary download URLs from message text. Retry delivery cannot create another capture or attach it twice.
8. Default bot replies contain status and a protected review link, without patient identifiers or transcript text. The review page supports correction and explicit patient/encounter selection; verify both capture ownership and current encounter access when attaching. Never attach to whichever patient happens to be open on another device. Link parameters are routing hints, not chart access. This is the proposed response-channel design; demonstrate it to the founders. Direct clinical transcript replies in ordinary chat require an explicit product/data-handling decision, not an unnoticed implementation shortcut.
9. Preserve raw recognized text and clinician corrections as separate revisions. Provider updates cannot silently overwrite a correction. Uncertain speaker identity remains unknown; do not label every utterance as a clinician observation. Task 004 owns clinical extraction and automatic form updates; this task must not invent diagnoses or approve notes.
10. Add authorized server events or bounded polling with revision/cursor recovery. After reconnect, fetch canonical state; never rely on events alone for persistence. Scope subscriptions and caches to current access and stop disclosure after revocation. On session expiry, allow reauthentication without quietly losing unsaved text; restore it only to the same authenticated actor and still-authorized encounter. Show another-device changes without overwriting the local editor.
11. Add private media storage and a documented, configurable retention/deletion policy. For synthetic staging, default raw audio to deletion within 24 hours and provide immediate discard; this is an engineering default, not a legal retention claim. Define provider-side and Telegram-side retention limits separately: deleting Clinora's copy is not proof those copies were erased. Keep production clinical capture disabled until its processing/retention arrangement is settled.

## Acceptance

- Real PostgreSQL/HTTP tests cover cross-clinic/capture access, wrong encounter attachment, expired/reused/stolen linking challenges, webhook forgery, duplicate updates, unauthorized media retrieval and revocation during processing.
- Restart workers during processing and retry the same upload/update. Exactly one current result and one attachment survive. Test conflicting chunk checksums, missing chunks, late completions after cancel/delete, provider timeout/rate limit and storage failure. No success state may conceal lost audio.
- Use two authenticated browser sessions: capture/attach on one, observe and reopen on the other; disconnect/reconnect; preserve a manual correction against later provider results. Replay authorization regressions from 002a remain required on new routes too.
- Exercise real microphone input on an available desktop and phone, and a native Telegram voice message through the configured bot and real STT adapter, using consenting participants reading fictional material. Mocked webhooks and prerecorded fixtures alone do not satisfy this live check. Record device/browser versions and what was not tested, particularly mobile background behavior.
- Establish a fixed synthetic speech set including a correction, negation, names/numbers, silence/noise and mixed-language speech. Confirm intended presentation languages; Uzbek/Russian are candidates to evaluate, not approved accuracy claims. Report transcription errors, first/final-result latency and measured cost. Record deficiencies for task 004/006; do not hide failures behind one clean English recording.
