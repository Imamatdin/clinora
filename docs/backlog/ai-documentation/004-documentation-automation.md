# Task 004 — Evidence-backed forms, review, approval and export

Issued 12 November 2026. Depends on task 003's persistent, revisioned transcripts and its access controls. Read `../REMAINING-TASKS.md`, existing document policies and migrations first. Preserve existing manually entered notes.

## Outcome

While the clinician speaks with the patient, the consultation draft fills incrementally using traceable transcript evidence. The clinician can inspect a field's source, correct it, resolve omissions/conflicts, approve an exact document version and export that approved version. Later changes become amendments; they do not rewrite the approved record.

## Implementation

1. Create a versioned template registry: specialty, document type, field keys/types, units, requiredness, display order, render mapping and provenance of the actual form. Use one shared encounter engine. Keep the generic notebook usable. Implement two materially different specialty templates to exercise extension points; choose them from supplied clinic forms. If forms are still absent, use clearly labelled synthetic templates and record that clinic-specific validation remains blocked. Do not invent official forms or claim every specialty is validated.
2. Use a server-side model adapter that returns schema-validated proposals, never arbitrary database operations. Each extraction run identifies transcript segment revisions, template/model/prompt version and its base document version. Verify every evidence reference belongs to this encounter and those exact input revisions. Text in a transcript or uploaded form is untrusted content, not authority to call tools, change roles, choose another patient or disclose records.
3. Build an incremental extraction scheduler with bounded debouncing, durable jobs and coalescing so every partial word does not create a model call. Track superseded runs. Apply only proposals whose dependencies are still valid; a late result cannot overwrite a newer correction, template choice, transcript revision or patient context. Persist original model proposals separately from accepted draft fields and clinician changes. Record model usage, latency and failure categories without general-log clinical text.
4. Keep patient reports, observations, measurements, history, current assessment and clinician instructions distinct. Missing values stay unrecorded; a denial of symptoms is not a normal examination. Preserve negation, laterality, units, dates and speaker uncertainty. Diagnoses mentioned by a patient are not automatically clinician-confirmed diagnoses. Contradictory or unsupported proposals become visible review items; numerical confidence must not be fabricated.
5. Protect clinician-edited fields from silent automated replacement. Show the conflicting proposed value and evidence, allowing accept/reject/edit. Transcript corrections invalidate affected proposals and visibly flag dependent fields for rereview; they do not erase an approved historical snapshot. Reuse confirmed facts across compatible documents with provenance. Do not copy an old visit's measurements into a new visit without explicit context and clinician confirmation.
6. Build the actual live review interface: updating fields, source excerpt/time range, uncertainty, required-but-missing information, manual corrections and concise error states. A clinician can continue manual documentation during a provider outage. Avoid jumping focus or resetting scroll as new segments arrive. Render clinical text as inert text; no unsanitized model HTML or script-bearing exports.
7. Implement persistent review and approval transactions behind the existing policy contracts. Approval requires current clinical authority, exact document ID/version/revision, explicit reviewed state and no unresolved blocking conflict. Bind any review acknowledgement to the version and invalidate it when that version changes. Approve version, actor, timestamp and audit atomically. Concurrent edits versus approval must yield a deterministic conflict, never approval of unseen content. A client-submitted approved flag is never authoritative.
8. Store approvals and approved snapshots immutably. Editing after approval creates an amendment with reason, parent approval and a new review/approval cycle. Historical originals remain identifiable. Current export loads the current approved snapshot server-side; a new unapproved amendment cannot be exported as approved. If historical approved export is supported, implement a separate explicit policy/route and label it historical/superseded; do not simply remove the existing stale-version guard.
9. Generate printable/downloadable documents from stored approved data using one canonical rendering pipeline. Include patient identity, visit date precision/location/clinician, document version, approval identity/time and amendment relationship where relevant. Never substitute entry date for visit date. Test Uzbek Latin/apostrophes and Cyrillic font coverage, pagination, long content and empty fields. A draft preview must be unmistakably unapproved. Avoid public document URLs or client-authored approval stamps.
10. Build clinic-form mapping as an adapter over the shared model so later forms do not demand a schema rewrite. Optional reference/protocol retrieval must use traceable sources and versions. Do not turn the documentation task into an autonomous diagnostic or prescribing engine. Preserve the founder's automation ambition through evidence-backed drafting and workflow preparation, not invented clinical decisions.

## Acceptance

- End-to-end: real synthetic speech -> revisioned transcript -> incrementally filled specialty form -> source inspection -> clinician correction -> further speech -> preserved correction -> review -> approval -> export -> restart/reopen identical approved version.
- Deterministic model-adapter tests cover malformed outputs, invented/foreign evidence, wrong segment revisions, prompt injection, ambiguous speakers, negation, absent examinations, changed units/laterality, stale jobs and provider failures. Grounding checks validate references; clinical correctness still needs human evaluation.
- Real PostgreSQL/HTTP concurrency tests cover edit-versus-approval, duplicate approval requests, late extraction after approval, revoked approval/export access, cross-patient versions, rollback on audit/storage failure, amendment history and exact-version export. Retain the task-002a cached-response tests.
- Test both templates with the same core. Saved template version and provenance survive template updates and restart. Export bytes/text must match the approved snapshot, including corrections; browser edits cannot alter the source of export.
- Run a fixed synthetic evaluation set with a real configured model. Measure field correctness, unsupported additions, omissions, correction effort, completion latency and cost. Include clinician review for the presentation cases before describing them as clinically validated. Failed cases and reviewer identity/date belong in the evidence; a golden-path model call is insufficient.
- Visually inspect desktop/phone review states and rendered exports. Test keyboard editing, conflict resolution and an unavailable-provider consultation completed manually. Real mic/STT/model checks remain separate from deterministic CI.

State which forms/specialties/languages were reviewed by clinicians and which remain synthetic. Task 005 may consume approved snapshots and explicit clinician instructions; it must not consume an arbitrary browser draft as an approved action.
